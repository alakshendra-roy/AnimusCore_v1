1. Executive Summary

On the critical execution path — order dispatch, tick ingestion, telemetry capture — the dominant latency cost is rarely the business logic itself. It is the serialization and IPC overhead surrounding it: marshalling a struct into a wire format, crossing a kernel syscall boundary, and copying the payload two to four times between producer and consumer. Conventional logging and messaging layers (synchronous file I/O, JSON/Protobuf encoding, socket-mediated queues) impose this cost on every single event, and that cost compounds directly into tail latency once thousands of events per second traverse the same path.

Animus Core removes that overhead structurally rather than optimizing around it: animus::sys::ipc::ShmRing<T> is a zero-allocation, lock-free single-producer/single-consumer (SPSC) ring buffer placed directly in shared memory. A producer writes a trivially-copyable record straight into a pre-sized slot — no heap allocation, no encode step, no syscall — and a consumer in a separate process reads that same memory directly. There is no wire format to parse because there is no wire; the struct layout in shared memory is the interchange format.

Measured on the reference configuration in Section 2, this architecture sustains a 30.3ns median (p50) per-event enqueue latency under a decoupled, non-blocking producer workload — see Section 3 for the full percentile distribution, methodology, and exact source citation, and Section 4 for the integration surface.

4. Hot-Path Integration Blueprint

The producer-side integration is two calls: create the ring once at startup, then call push_overwrite() on the hot path. It never allocates, never blocks, and never refuses a write — a full ring reclaims its oldest unread slot and increments a deterministic drop counter instead of applying backpressure to the caller. This is the real API surface from include/animus/shm_ipc.hpp and include/animus/execution_event.hpp, not a simplified pseudocode stand-in.

C++17 · telemetry_record.cpp
// One-time setup: a 40-byte, trivially-copyable wire record and a
// zero-allocation SPSC ring placed directly in shared memory.
#include "animus/shm_ipc.hpp"
#include "animus/execution_event.hpp"

using animus::ExecutionEvent;
using animus::sys::ipc::ShmRing;

auto ring = ShmRing<ExecutionEvent>::create("animus_telemetry", 4096);

// Hot path: zero heap allocation, never blocks, never refuses a write.
void record_execution_event(uint64_t seq, int64_t price_ticks, int64_t qty, uint32_t instrument_id) {
    ExecutionEvent evt{};
    evt.sequence        = seq;
    evt.dispatch_ts_raw = __rdtsc();          // serialized read, see Section 2
    evt.price_ticks     = price_ticks;
    evt.quantity        = qty;
    evt.instrument_id   = instrument_id;

    ring->push_overwrite(evt);                // non-blocking; drops oldest unread slot if full
}

// Deterministic loss visibility — always 0 if the consumer keeps pace.
uint64_t dropped = ring->dropped_count();

A consumer in a separate process — C++ via ShmRing<ExecutionEvent>::open(), or Python via the nanobind binding in bindings/animus_shm_py.cpp — attaches to the same named segment and reads the identical struct layout with no decode step in between.

5. Institutional Pilot Verification Protocol

These are the same three steps we run to reproduce Section 3's numbers on a prospect's own hardware during pilot onboarding — nothing here depends on machinery you cannot see.

  1. 01
    Build the harness from source

    Clone the eval kit and compile benchmarks/harness_benchmark.cpp against your own toolchain (no vendored binary): g++ -std=c++17 -O3 -march=native -Iinclude benchmarks/harness_benchmark.cpp -o harness_benchmark -lpthread.

  2. 02
    Run the producer, attach the consumer

    Launch ./harness_benchmark --events 10000000 --mode overwrite and, for a full loss-accounting pass, attach eval_kit/scripts/verify_stream.py from a second, genuinely separate OS process before the run completes.

  3. 03
    Cross-check sequence gaps against dropped_count()

    The consumer's observed sequence gaps must equal the producer's own dropped_count() exactly. Any mismatch is a real correctness finding, not a rounding difference — treat it as a stop-ship signal during your own pilot, the same way we do.
