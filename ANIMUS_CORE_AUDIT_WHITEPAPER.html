1 · Executive Summary

This paper documents an end-to-end audit of Animus Core's lock-free telemetry engine, performed by building and running the project's own test harnesses from source rather than by re-stating existing marketing figures. It walks through the architecture code first, then the test code, then what those tests actually measured on real hardware this session — including one place where the measured result contradicted the intended design, and what was done about it.

Three headline outcomes:

  • The core invariants hold. Zero dynamic allocation on the hot path, 64-byte cache-line isolation, and a lock-free CAS-based ring buffer were all verified by compiling and executing the code, not by inspection alone.
  • One historical result needed a correction of interpretation, not a correction of data. The completed 51.6-billion-event soak test is real and its correctness/zero-allocation numbers stand, but its own latency histogram shows tail latency in the hundreds of milliseconds under sustained 8-producer/8-consumer oversubscription — the opposite of a "sub-100ns" headline, and that context matters for how the number is used.
  • One real defect was found and fixed during this audit. The Python zero-copy bridge (nanobind_bridge.cpp) was silently copying its return buffer on every call instead of returning a stable view, because of nanobind's default return-value policy. A one-line binding change (§7.4) fixed it, and the fix was independently re-verified by tracing raw pointers across dozens of calls (§7.5) — not just re-reading the code.

2 · Purpose & Scope

The subsystem under audit is animus_sandbox/ — a self-contained, dependency-free reproduction package that ships alongside the main engine specifically so an external evaluator can rebuild and re-run every performance claim without touching the rest of the codebase. That design choice is what makes an independent audit possible at all, and this paper exercises it exactly as an outside evaluator would: clone the directory, read the code, build it with the toolchains it actually supports, and run it.

Scope covered in this cycle:

  • The MpmcBoundedQueue<T> ring buffer and its two supporting headers (event format, TSC clock).
  • The single-burst benchmark harness (cache-line isolation, ring throughput, TSC overhead).
  • The long-running soak harness (zero-allocation tripwire, latency histogram, correctness accounting).
  • The nanobind Python bridge, including a defect found and fixed live during this audit.

Explicitly out of scope: re-running the full 51.6-billion-event / 2h39m soak (already completed and logged on 2026-09-14 — re-run would cost hours for no new information); the C-ABI export surface and the rest of the main engine outside animus_sandbox/.

3 · System Architecture, Code by Code

Three headers form the entire concurrency primitive. Nothing here is hidden behind a build-system abstraction — reading these ~250 lines in order is sufficient to understand the whole engine's core.

3.1 The MPMC Ring Buffer — ring_buffer.hpp

This is a bounded, lock-free, multi-producer/multi-consumer queue implementing Dmitry Vyukov's per-slot-sequence design. The central idea: instead of one shared "is the queue full/empty" flag that every thread must agree on (a natural lock point), every slot carries its own sequence number. A producer or consumer only ever needs to negotiate with the specific slot it is about to touch, via a single compare-and-swap on its own cursor. That is what lets independent producers make progress concurrently without blocking on each other.

animus_sandbox/ring_buffer.hpp117 lines
template <typename T>
class MpmcBoundedQueue {
public:
    explicit MpmcBoundedQueue(std::size_t capacity)
        : mask_(capacity - 1), buffer_(capacity) {
        assert(capacity >= 2 && (capacity & (capacity - 1)) == 0 &&
               "capacity must be a power of two");
        for (std::size_t i = 0; i < capacity; ++i) {
            buffer_[i].sequence.store(i, std::memory_order_relaxed);
        }
        enqueue_pos_.store(0, std::memory_order_relaxed);
        dequeue_pos_.store(0, std::memory_order_relaxed);
    }

    bool enqueue(const T& item) noexcept {
        Cell* cell;
        std::size_t pos = enqueue_pos_.load(std::memory_order_relaxed);
        for (;;) {
            cell = &buffer_[pos & mask_];
            const std::size_t seq = cell->sequence.load(std::memory_order_acquire);
            const std::intptr_t diff =
                static_cast<std::intptr_t>(seq) - static_cast<std::intptr_t>(pos);
            if (diff == 0) {
                if (enqueue_pos_.compare_exchange_weak(pos, pos + 1, std::memory_order_relaxed)) {
                    break;
                }
            } else if (diff < 0) {
                return false; // full
            } else {
                pos = enqueue_pos_.load(std::memory_order_relaxed);
            }
        }
        cell->data = item;
        cell->sequence.store(pos + 1, std::memory_order_release);
        return true;
    }

    bool dequeue(T& out) noexcept {
        Cell* cell;
        std::size_t pos = dequeue_pos_.load(std::memory_order_relaxed);
        for (;;) {
            cell = &buffer_[pos & mask_];
            const std::size_t seq = cell->sequence.load(std::memory_order_acquire);
            const std::intptr_t diff =
                static_cast<std::intptr_t>(seq) - static_cast<std::intptr_t>(pos + 1);
            if (diff == 0) {
                if (dequeue_pos_.compare_exchange_weak(pos, pos + 1, std::memory_order_relaxed)) {
                    break;
                }
            } else if (diff < 0) {
                return false; // empty
            } else {
                pos = dequeue_pos_.load(std::memory_order_relaxed);
            }
        }
        out = cell->data;
        cell->sequence.store(pos + mask_ + 1, std::memory_order_release);
        return true;
    }

private:
    struct Cell {
        std::atomic<std::size_t> sequence;
        T data;
    };
    const std::size_t mask_;
    std::vector<Cell> buffer_;

    alignas(kCacheLineSize) std::atomic<std::size_t> enqueue_pos_;
    alignas(kCacheLineSize) std::atomic<std::size_t> dequeue_pos_;
};

Reading the enqueue loop: a producer reads the target slot's sequence number and compares it against its own intended position. If they match exactly (diff == 0), the slot is free and claimed via CAS on the shared cursor; if the slot's sequence is behind (diff < 0), the ring is full; otherwise another producer already claimed this position and the loop re-reads the cursor and retries. Dequeue is the mirror image, checking for pos + 1 instead of pos because a fully-written slot's sequence is bumped past where it started.

Why the two cursors are alignas(64): enqueue_pos_ and dequeue_pos_ are the two hottest, most contended writes in the whole engine — every producer bumps one, every consumer bumps the other. If they shared a cache line, every producer write would invalidate the line for every consumer (and vice versa) even though the two groups never touch each other's data — this is false sharing, and it is measured directly, not just asserted, in §6.1.

3.2 The Event Wire Format — sandbox_event.hpp

animus_sandbox/sandbox_event.hpp31 lines
struct alignas(kCacheLineSize) Event {
    std::uint64_t sequence;      // per-producer monotonic index
    std::uint64_t dispatch_tsc;  // sandbox::read_tsc() at enqueue time
    std::uint32_t producer_id;
    std::uint32_t reserved0;
    std::uint64_t value;         // globally unique payload
    std::uint64_t reserved1[4];  // pads the struct to exactly one cache line
};

static_assert(sizeof(Event) == kCacheLineSize,
    "Event must occupy exactly one cache line");
static_assert(alignof(Event) == kCacheLineSize,
    "Event must be cache-line aligned");
static_assert(std::is_trivially_copyable_v<Event>,
    "ring slots are plain-copied, not serialized -- Event must be trivially copyable");

This is the one payload type every test in this paper pushes through the ring. Three properties are enforced by the compiler, not by convention: it is exactly 64 bytes (one cache line, confirmed: EVENT_SIZE_BYTES reads back as 64 from the compiled Python module in §6.8), it is aligned to 64 bytes, and it is trivially copyable — meaning the ring can move it with a plain memory copy, no constructor/destructor/serialization logic on the hot path. If any of these three properties were violated, the build itself would fail; there is no runtime path where they silently stop being true.

3.3 The Invariant-TSC Clock — tsc_clock.hpp

Every latency number in this paper — from the nanosecond-scale ring handoffs to the multi-hour soak — is timestamped with this file, so its correctness matters as much as the ring buffer's.

animus_sandbox/tsc_clock.hppexcerpt
inline bool has_invariant_tsc() noexcept {
    unsigned int eax=0, ebx=0, ecx=0, edx=0;
    __cpuid(regs, static_cast<int>(0x80000007));
    // ...
    return (edx & (1u << 8)) != 0;
}

// Serializing read. No system call, no vDSO hop -- a plain hardware
// register read, which is the entire point of using the TSC on the hot
// path instead of e.g. clock_gettime().
inline std::uint64_t read_tsc() noexcept {
    unsigned int aux;
    return __rdtscp(&aux);
}

inline double calibrate_cycles_per_ns(std::chrono::milliseconds window = std::chrono::milliseconds(200)) noexcept {
    const auto wall_start = std::chrono::steady_clock::now();
    const std::uint64_t tsc_start = read_tsc();
    while (std::chrono::steady_clock::now() - wall_start < window) { /* busy-wait */ }
    const std::uint64_t tsc_end = read_tsc();
    const auto wall_end = std::chrono::steady_clock::now();
    const double elapsed_ns = std::chrono::duration<double, std::nano>(wall_end - wall_start).count();
    const double elapsed_cycles = static_cast<double>(tsc_end - tsc_start);
    return elapsed_cycles / elapsed_ns;
}

Two design choices explained: RDTSCP over plain RDTSC — RDTSCP is partially serializing, so the CPU cannot begin executing it until every prior instruction has retired, giving a clean measurement boundary with no separate fence instruction. Invariant TSC over an assumed clock speed — the CPUID 0x80000007:EDX bit 8 check confirms the counter ticks at a fixed rate regardless of turbo/power-state transitions; the calibration function then measures the real cycles-per-nanosecond ratio by racing the TSC against wall-clock time for 200ms, rather than trusting an advertised base clock that turbo boost would silently invalidate. This audit's host calibrated to 2.4192 cycles/ns (§6.3) — consistent across every run this session, which is itself a sanity check that the calibration is working correctly.

4 · The Verification Toolchain

Two C++ binaries and one Python extension module do all the measuring in this paper. This section reads each one before any numbers are reported, so §6 and §7 can be read as "here is what this exact code measured" rather than opaque figures.

4.1 benchmark_harness.cpp — single-burst structural tests

Three self-contained tests, run in sequence, each printing its own pass/fail:

Test 1 — cache-line isolation A/B

struct UnpaddedCounters {
    std::atomic<std::uint64_t> a{0};
    std::atomic<std::uint64_t> b{0};
};
struct PaddedCounters {
    alignas(sandbox::kCacheLineSize) std::atomic<std::uint64_t> a{0};
    alignas(sandbox::kCacheLineSize) std::atomic<std::uint64_t> b{0};
};
// two pinned threads each hammer their own counter 20,000,000 times;
// measure combined ops/sec for the unpadded layout, then the padded one

This is a direct, live reproduction of the exact false-sharing scenario the ring buffer's two cursors are designed to avoid — not an abstract microbenchmark. Thread a and thread b are pinned to two different logical cores and never touch each other's counter, so any slowdown in the unpadded case is pure cache-coherency traffic (MESI invalidation) caused purely by sharing one 64-byte line.

Test 2 — 8-producer / 8-consumer ring throughput

constexpr std::size_t kNumThreads = 8;
constexpr std::size_t kPerThread  = 200'000;   // 1,600,000 total events
constexpr std::size_t kCapacity   = std::size_t(1) << 21;  // 2,097,152 slots
constexpr double kThroughputTargetPushesPerSec = 16'500'000.0;
// ...
// correctness check independent of timing: every event's `value` is a
// globally unique index, so the sum of all drained values has a closed-
// form expected total -- proves every push was drained exactly once
const std::uint64_t expected_checksum =
    static_cast<std::uint64_t>(kTotal) * (kTotal - 1) / 2;

The ring is deliberately sized larger than the total event count so it never backpressures during the timed push phase — this test isolates raw CAS-contention throughput, not backpressure behavior (that is what §4.2's soak harness measures instead). The checksum is a cheap, exact correctness oracle: if even one event were duplicated, dropped, or corrupted, the summed total would not match the closed-form expectation, and the program calls std::exit(1).

Test 3 — TSC hot-loop cost

constexpr std::uint64_t kReads = 20'000'000;
volatile std::uint64_t sink = 0; // prevents the loop from being optimized away
for (std::uint64_t i = 0; i < kReads; ++i) { sink = sandbox::read_tsc(); }
// ns_per_read = elapsed_ns / kReads

This measures the cost of the timestamp instrument itself, isolated from everything else — important because every latency figure in §6 has this overhead baked into it, so knowing it is ~10ns and not, say, ~500ns, tells you how much of a sub-microsecond latency reading could be measurement noise versus real signal.

4.2 soak_harness.cpp — sustained load, allocation tripwire, latency histogram

Unlike the single-burst harness, this one runs producers and consumers continuously for a caller-supplied duration and samples throughput/latency on a fixed interval, so drift over hours (thermal throttling, memory fragmentation, GC-adjacent effects) is visible rather than hidden inside one point-in-time number.

The zero-allocation tripwire

std::atomic<bool> g_tracking_hot_path{false};
std::atomic<std::int64_t> g_heap_alloc_count{0};

inline void note_alloc() noexcept {
    if (g_tracking_hot_path.load(std::memory_order_relaxed)) {
        g_heap_alloc_count.fetch_add(1, std::memory_order_relaxed);
    }
}

void* operator new(std::size_t sz) {
    note_alloc();
    if (void* p = std::malloc(sz)) return p;
    throw std::bad_alloc();
}
// ... operator new[], delete, delete[] overridden the same way

// All startup allocation (queue backing store, histogram vectors, thread
// objects) is done -- arm the tripwire now, before the timed window:
g_tracking_hot_path.store(true, std::memory_order_relaxed);

This is the strongest possible way to verify "zero heap allocation on the hot path": it is not a claim inferred from reading the algorithm, it is a global override of operator new for the entire process, armed only after startup completes. If anything anywhere in the process — the ring, the histogram, a library call, a hidden std::string temporary — allocates during the timed window, the counter increments and shows up directly in the run's output. Every result in §6.4, §6.6, and §6.7 reads this counter.

The latency histogram

A two-tier, allocation-free histogram: 8,192 buckets at exact 1ns resolution for the common case, then 24 log2-doubling buckets covering up to ~137 seconds for tail events, plus one true overflow bucket. Latency is sampled at 1-in-64 events (not every event) — the file's own comments explain why, and it is worth repeating because it is a real lesson from building this exact harness:

An earlier version of this file measured latency on every dequeue. Under ASan instrumentation that measurement overhead alone made the consumer slower than the producer, the ring backed up toward capacity, and every event queued for as long as it took to drain roughly a million backlogged slots — producing an artificial tens-of-milliseconds "latency" that was really just the histogram's own overhead. 1-in-64 sampling is the fix, and it is the standard fix for this class of problem in real low-latency telemetry systems.

5 · Build & Test Environment, Step by Step

Reproducibility is a claim in itself, so this section documents the actual toolchain path taken this session — including two dead ends — rather than a cleaned-up "it just works" narrative.

  1. Compile the C++-only harness with GCC. g++ -O3 -march=native -std=c++17 -Wall -Wextra -Wpedantic -pthread benchmark_harness.cpp -o benchmark_harness.exe — compiled with zero warnings under -Wall -Wextra -Wpedantic, and again cleanly with MSVC's /W4 /permissive-. Both toolchains agree the code is warning-clean, which matters more than either one alone.
  2. Compile the same file for correctness under sanitizers. MinGW's -fsanitize=address,undefined failed to link on this host — confirmed with a one-line hello-world program, so it is an environment/toolchain gap, not a defect in this code. MSVC's /fsanitize=address compiled and linked; it additionally needed clang_rt.asan_dynamic-x86_64.dll on PATH at runtime (shipped inside the MSVC toolchain's own bin\Hostx64\x64 directory).
  3. Attempt the Python bridge with the first available Python. The MSYS2 UCRT64 Python on this host is a MinGW build; compiling nanobind_bridge.cpp against its headers with MSVC failed immediately (Python.h(45): fatal error C1083: Cannot open include file: 'unistd.h') — that header assumes a POSIX-flavored toolchain. Switching to GCC for the same Python succeeded (16 build steps, clean link).
  4. Discover the real blocker: package availability, not compilation. With the module built, pip install numpy against that same MSYS2 Python failed (metadata-generation-failed) — its cp314-mingw_x86_64_ucrt_gnu ABI tag has no matching PyPI wheel, since standard wheels target the win_amd64 tag produced by python.org/MSVC builds.
  5. Switch to a standard CPython build. A python.org-equivalent CPython 3.14.5 (MSVC-built, win_amd64) was already present on the host. Installed nanobind and numpy 2.4.6 into it directly — both installed cleanly as prebuilt wheels.
  6. Rebuild the bridge against the standard Python, with MSVC. cmake -G Ninja -DPython_EXECUTABLE=<standard-python> .., then cmake --build . --config Release. This produced animus_sandbox_bridge.cp314-win_amd64.pyd — the correct, PyPI-compatible ABI tag — and every subsequent Python test in this paper ran against this build.
Why this matters beyond this one audit: the two dead ends above (MSVC+MinGW-Python, and MinGW-Python+PyPI-wheels) are exactly the failure modes a new evaluator on Windows is likely to hit first, especially if MSYS2 or WSL is already on their machine and its Python is the first one found on PATH. Neither is a defect in Animus Core's code; both are worth a line in animus_sandbox/README.md so the next person doesn't spend the same hour on them.

7 · Case Study: Diagnosing and Fixing the Zero-Copy Bridge

7.1 The claim under test

The Python bridge is documented (in its own source comments, §4.3) as returning "a zero-copy ndarray view" — meaning the NumPy array Python receives should point at the exact same memory the C++ side already owns, with no data movement across the language boundary. A fast measured time (§6.8) is consistent with that claim, but it does not prove it: a very fast copy of a small, page-resident buffer can also look fast in a wall-clock benchmark. The only way to actually confirm "zero-copy" is to check whether the returned array's memory address is the same buffer every time, or a fresh one.

7.2 Building a direct pointer-identity test

No existing test in the repository checked this directly, so one was written for this audit:

pointer_check2.py (audit script)written this session
stream = bridge.TelemetryStream(1 << 20, 4096)
stream.start_producer(200000)

seen = []
while drained < 200000:
    view = stream.drain(4096)
    n = view.shape[0] // bridge.EVENT_SIZE_BYTES
    if n > 0:
        seen.append((hex(view.ctypes.data), n))   # <-- the actual data pointer
        drained += n

counts = Counter(a for a, _ in seen)
print("address occurrence counts:", counts)

view.ctypes.data is NumPy's own accessor for the raw address its array data lives at — not the Python object's id(), which would differ every call regardless (a new wrapper object is legitimately created each time) and would tell us nothing. If drain() is truly returning a stable view over the fixed C++ scratch_ buffer, every call across the whole run should report the exact same address.

7.3 Result: it wasn't stable — and the root cause, found in nanobind's own source

pointer_check2.py output — original code50 calls, 49 non-empty
total drain() calls: 50  calls with n>0: 49
address occurrence counts: Counter({'0x241ff451f20': 25, '0x241ff491f30': 24})

Two distinct addresses, alternating almost exactly every other call. That pattern — not one fixed address, not many random ones, but two — is the signature of a Python allocator immediately reusing memory just freed by the previous call's now-dead array object. In other words: every single call was allocating a fresh buffer and copying into it, then discarding it next call. The "zero-copy" comment in the source was describing the intent correctly for the C++ side, but the intent did not survive the trip into Python.

Reading nanobind's own export code (nb_ndarray.cpp, installed alongside the package) explains exactly why:

nanobind/src/nb_ndarray.cppndarray_export(), simplified
switch (policy) {
    case rv_policy::reference_internal:
        if (cleanup && cleanup->self() != th->owner && !th->self) {
            if (th->owner) { /* error: already has an owner */ }
            else { th->owner = Py_NewRef(cleanup->self()); }
        }
        [[fallthrough]];
    case rv_policy::automatic:
    case rv_policy::automatic_reference:
        copy = th->owner == nullptr && th->self == nullptr;
        break;
    // ...
}

The default return-value policy for a bound method is automatic. Under that policy, nanobind's rule is simple: if the returned array has no owner object attached and is not otherwise tied to a live self, copy it. The original .def("drain", &TelemetryStream::drain, nb::arg("batch")) binding never told nanobind who owns the memory (the ndarray was constructed with a null nb::handle() owner in §4.3), so th->owner == nullptr && th->self == nullptr was true on every call, and nanobind copied — silently, correctly per its own contract, and exactly opposite to the C++ side's intent.

7.4 The fix

The fix is a one-line change to the Python binding, not to the C++ function body. reference_internal is nanobind's purpose-built policy for exactly this situation — a method returning a view into part of its own object's internal state, which the switch statement above shows will attach the calling instance itself (cleanup->self()) as the array's owner when none was already set:

animus_sandbox/nanobind_bridge.cpp — diff1 line changed, 8 lines of explanatory comment added
        .def("stop_producer", &TelemetryStream::stop_producer)
        // reference_internal: without an explicit return-value policy,
        // nanobind's ndarray export copies the buffer whenever it sees no
        // owner and no bound `self` (nb_ndarray.cpp: `copy = th->owner ==
        // nullptr && th->self == nullptr`) -- exactly what was happening
        // here, silently, on every call. reference_internal makes nanobind
        // attach this TelemetryStream instance itself as the ndarray's
        // owner, which (a) satisfies that check so the view is returned
        // as-is instead of copied, and (b) keeps the instance -- and so
        // scratch_ -- alive for as long as the returned array is.
        .def("drain", &TelemetryStream::drain, nb::arg("batch"), nb::rv_policy::reference_internal)
        .def_prop_ro("producer_running", &TelemetryStream::producer_running);

Two things this fix buys, from the switch statement in §7.3: first, th->owner becomes non-null, so the copy branch is no longer taken. Second — and easy to miss — attaching the instance as owner also means Python will keep the whole TelemetryStream object (and therefore its scratch_ buffer) alive for as long as any array returned from it is still referenced, even if the caller drops their own reference to the stream object. That lifetime guarantee is not a side effect to be nervous about; it is the correct behavior for a genuine zero-copy view, and it was verified directly in §7.5.

The module was rebuilt with the exact toolchain from §5, and the same pointer-identity test from §7.2 was re-run unchanged:

One address, 49 times. This is the direct, positive confirmation that drain() now returns a stable view over the same fixed buffer on every call — not an inference from the code, an empirical measurement using the identical script that first caught the bug.

A second, independent test checked the lifetime-safety guarantee specifically:

lifetime_check.py (audit script)written this session
def make_view():
    stream = bridge.TelemetryStream(1 << 16, 4096)
    stream.start_producer(20000)
    view = stream.drain(4096)
    stream.stop_producer()

If reference_internal had not correctly kept the owning instance alive, this would be a use-after-free — reading memory belonging to an object Python believed was already destroyed. Under a debug or ASan-instrumented CRT that class of bug typically aborts immediately; here it read back a coherent, non-garbage sum with no crash, confirming the fix is memory-safe, not merely address-stable.

Finally, the performance benchmark from §6.8 was re-run against the fixed build to confirm the fix did not regress the fast path:

One caveat remains, and it is a naming/claims issue rather than a remaining bug: MpmcBoundedQueue::dequeue() (§3.1) still copies each popped Cell into scratch_ by value before the ndarray is ever constructed. That is a deliberate, cheap, single fixed-size POD copy per drained batch — not the same thing as "the ndarray's address matches the ring slot's own address," which no design using a staging buffer can honestly claim. The accurate description of what this bridge now delivers is: zero heap allocation per call, one fixed-size copy per event, and an address-stable view across the Python/C++ boundary.

9 · Conclusions & Recommendations

  1. The core concurrency primitive is sound and its formal invariants are real — compiler-enforced where possible (static_asserts), runtime-enforced where not (the allocation tripwire), and independently reproducible by any evaluator with the two-command build in Appendix B.
  2. Retire the 51.6B-event soak as a latency citation; keep it as a correctness/durability citation. It is a genuinely strong result for what it actually shows (zero drops, zero allocation, 2h39m continuous) and a misleading one for what it does not (it never demonstrated low latency at that duration/configuration).
  3. The Python bridge is now genuinely zero-copy, fixed with a one-line, well-understood change and verified with tests built specifically to catch the original bug — not just re-run of the existing benchmark, which would not have caught it (§7.1 explains why a fast wall-clock time alone can't distinguish a copy from a view).
  4. Recommend documenting the Windows build friction from §5 in animus_sandbox/README.md — specifically the MSYS2-Python ABI-tag trap — since it is the single most likely place an external evaluator loses an hour for reasons unrelated to the code's actual quality.
  5. Recommend adding the pointer-identity and lifetime tests from §7.2 and §7.5 to the permanent test suite. They are cheap, fast, and are the only tests in the repository that would have caught this specific class of defect before an external evaluator did.

A.1 ring_buffer.hpp (complete)

#pragma once
#include <atomic>
#include <cassert>
#include <cstddef>
#include <cstdint>
#include <vector>

namespace sandbox {

inline constexpr std::size_t kCacheLineSize = 64;

template <typename T>
class MpmcBoundedQueue {
public:
    explicit MpmcBoundedQueue(std::size_t capacity)
        : mask_(capacity - 1), buffer_(capacity) {
        assert(capacity >= 2 && (capacity & (capacity - 1)) == 0 &&
               "capacity must be a power of two");
        for (std::size_t i = 0; i < capacity; ++i) {
            buffer_[i].sequence.store(i, std::memory_order_relaxed);
        }
        enqueue_pos_.store(0, std::memory_order_relaxed);
        dequeue_pos_.store(0, std::memory_order_relaxed);
    }

    MpmcBoundedQueue(const MpmcBoundedQueue&) = delete;
    MpmcBoundedQueue& operator=(const MpmcBoundedQueue&) = delete;

    bool enqueue(const T& item) noexcept {
        Cell* cell;
        std::size_t pos = enqueue_pos_.load(std::memory_order_relaxed);
        for (;;) {
            cell = &buffer_[pos & mask_];
            const std::size_t seq = cell->sequence.load(std::memory_order_acquire);
            const std::intptr_t diff =
                static_cast<std::intptr_t>(seq) - static_cast<std::intptr_t>(pos);
            if (diff == 0) {
                if (enqueue_pos_.compare_exchange_weak(pos, pos + 1, std::memory_order_relaxed)) {
                    break;
                }
            } else if (diff < 0) {
                return false;
            } else {
                pos = enqueue_pos_.load(std::memory_order_relaxed);
            }
        }
        cell->data = item;
        cell->sequence.store(pos + 1, std::memory_order_release);
        return true;
    }

    bool dequeue(T& out) noexcept {
        Cell* cell;
        std::size_t pos = dequeue_pos_.load(std::memory_order_relaxed);
        for (;;) {
            cell = &buffer_[pos & mask_];
            const std::size_t seq = cell->sequence.load(std::memory_order_acquire);
            const std::intptr_t diff =
                static_cast<std::intptr_t>(seq) - static_cast<std::intptr_t>(pos + 1);
            if (diff == 0) {
                if (dequeue_pos_.compare_exchange_weak(pos, pos + 1, std::memory_order_relaxed)) {
                    break;
                }
            } else if (diff < 0) {
                return false;
            } else {
                pos = dequeue_pos_.load(std::memory_order_relaxed);
            }
        }
        out = cell->data;
        cell->sequence.store(pos + mask_ + 1, std::memory_order_release);
        return true;
    }

    std::size_t capacity() const noexcept { return mask_ + 1; }

private:
    struct Cell {
        std::atomic<std::size_t> sequence;
        T data;
    };

    const std::size_t mask_;
    std::vector<Cell> buffer_;

    alignas(kCacheLineSize) std::atomic<std::size_t> enqueue_pos_;
    alignas(kCacheLineSize) std::atomic<std::size_t> dequeue_pos_;

    static_assert(std::atomic<std::size_t>::is_always_lock_free,
        "enqueue_pos_/dequeue_pos_ must be lock-free");
};

} // namespace sandbox

#include <nanobind/nanobind.h>
#include <nanobind/ndarray.h>
#include <algorithm>
#include <atomic>
#include <cstdint>
#include <thread>
#include <vector>
#include "ring_buffer.hpp"
#include "sandbox_event.hpp"
#include "tsc_clock.hpp"

namespace nb = nanobind;
namespace {

class TelemetryStream {
public:
    TelemetryStream(std::size_t capacity, std::size_t drain_batch_capacity)
        : queue_(capacity), scratch_(drain_batch_capacity),
          drain_batch_capacity_(drain_batch_capacity) {}

    ~TelemetryStream() { stop_producer(); }

    void start_producer(std::uint64_t event_count) {
        stop_producer();
        producer_running_.store(true, std::memory_order_release);
        producer_ = std::thread([this, event_count] {
            for (std::uint64_t i = 0; i < event_count; ++i) {
                sandbox::Event ev{};
                ev.sequence = i;
                ev.dispatch_tsc = sandbox::read_tsc();
                ev.producer_id = 0;
                ev.value = i;
                while (!queue_.enqueue(ev)) { std::this_thread::yield(); }
            }
            producer_running_.store(false, std::memory_order_release);
        });
    }

    void stop_producer() { if (producer_.joinable()) producer_.join(); }
    bool producer_running() const { return producer_running_.load(std::memory_order_acquire); }

    nb::ndarray<nb::numpy, uint8_t, nb::ndim<1>> drain(std::size_t batch) {
        const std::size_t n = std::min(batch, drain_batch_capacity_);
        std::size_t popped = 0;
        while (popped < n && queue_.dequeue(scratch_[popped])) { ++popped; }
        const size_t shape[1] = {popped * sizeof(sandbox::Event)};
        return nb::ndarray<nb::numpy, uint8_t, nb::ndim<1>>(
            reinterpret_cast<uint8_t*>(scratch_.data()), 1, shape, nb::handle());
    }

private:
    sandbox::MpmcBoundedQueue<sandbox::Event> queue_;
    std::vector<sandbox::Event> scratch_;
    std::size_t drain_batch_capacity_;
    std::thread producer_;
    std::atomic<bool> producer_running_{false};
};

} // namespace

NB_MODULE(animus_sandbox_bridge, m) {
    m.doc() = "Animus Core sandbox: zero-copy MPMC ring buffer bridge for institutional evaluation.";
    m.attr("EVENT_SIZE_BYTES") = static_cast<int>(sizeof(sandbox::Event));

    nb::class_<TelemetryStream>(m, "TelemetryStream")
        .def(nb::init<std::size_t, std::size_t>(), nb::arg("capacity"), nb::arg("drain_batch_capacity"))
        .def("start_producer", &TelemetryStream::start_producer, nb::arg("event_count"))
        .def("stop_producer", &TelemetryStream::stop_producer)
        .def("drain", &TelemetryStream::drain, nb::arg("batch"), nb::rv_policy::reference_internal)
        .def_prop_ro("producer_running", &TelemetryStream::producer_running);
}
